# الدليل التقني الشامل لبوت الحماية والمراقبة (Crypto Security Bot)

هذا المستند يشرح بالتفصيل كيفية عمل البوت خطوة بخطوة، بدءاً من الإعداد وصولاً إلى إصدار التقارير النهائية.

---

## 1. الهيكلية المعمارية (Architecture)
يعمل البوت بناءً على نظام الوحدات المنفصلة (Modular System)، حيث تتحمل كل وحدة مسؤولية محددة:
- **نظام الإدارة**: `admin_cli.py` (لإضافة الشركات والمفاتيح، وتنفيذ السحب اليدوي).
- **نظام الإعدادات**: `config.py` (لقراءة البيانات من `clients.json`).
- **نظام المراقبة**: `monitor.py` (لمسح المنصات وحفظ السجل في `history.json`).
- **نظام الحماية**: `security.py` (للتحقق من إذن المطور).
- **نظام الأتمتة**: `automation.py` (لتنفيذ العمليات الآلية).
- **نظام التقارير**: `reporter.py` (لتحويل البيانات إلى تقارير PDF/CSV).

---

## 2. رحلة العمل خطوة بخطوة (Step-by-Step Workflow)

### الخطوة 1: التهيئة (Initialization)
عند تشغيل الملف الرئيسي `bot.py`:
1. يقوم الكلاس `Config` بقراءة ملف `clients.json`.
2. لكل شركة (Client) موجودة في الملف، يتم إنشاء كائن (Object) خاص بها يحتوي على نظام المراقبة والأتمتة الخاص بها بناءً على مفاتيح الـ API المزودة.

### الخطوة 2: بدء المراقبة وحفظ السجل (Monitoring & History)
يدخل البوت في حلقة (Loop) مستمرة:
1. يتصل البوت بالمنصات (مثل Binance) باستخدام مكتبة `ccxt`.
2. يقوم بطلب قائمة الإيداعات (Deposits) والسحوبات (Withdrawals) الأخيرة.
3. يتم تسجيل أي حركة جديدة في السجل الداخلي وفي ملف `history.json` لضمان استمرارية البيانات.

### الخطوة 3: تفعيل نظام الأتمتة والحماية (Automation & Security)
عند الرغبة في تحويل الأموال أو استقبالها:
1. يطلب نظام الأتمتة (`AutomationEngine`) إذناً من كلاس `SecurityLayer`.
2. يتم التحقق: هل الـ `DEVELOPER_AUTH_TOKEN` المرسل يطابق الرمز السري المخزن؟
   - **نعم**: يتم إرسال طلب السحب للمنصة وتنفيذ العملية فوراً بدون تدخل بشري.
   - **لا**: يتم رفض العملية وتسجيل محاولة اختراق أو "وصول غير مصرح به".

### الخطوة 4: السحب اليدوي والمراقبة التاريخية (Manual Control)
يمكن للمطور الآن التحكم بالبوت عبر `admin_cli.py`:
1. **السحب اليدوي**: تنفيذ عملية سحب لأي عميل مباشرة باستخدام مفاتيح الـ API الخاصة به.
2. **عرض التاريخ**: الاطلاع على آخر المعاملات المخزنة في النظام.

### الخطوة 5: الإنهاء وإصدار التقارير (Reporting)
عند إيقاف البوت:
1. يتم إرسال جميع السجلات المجمعة إلى كلاس `Reporter`.
2. يتم إنشاء ملفين لكل شركة: `report_[client_id].pdf` و `report_[client_id].csv`.

---

## 3. كيفية البيع كخدمة (SaaS Business Model)
بما أن البوت يدعم "تعدد المستأجرين" (Multi-tenancy)، يمكنك استخدامه كالتالي:
1. **الاستضافة**: قم بتشغيل البوت على سيرفر خاص بك (VPS).
2. **إضافة العملاء**: لكل شركة تشتري الخدمة، استخدم `admin_cli.py` لإضافتها وتزويدها برمز مطور خاص بها.
3. **توزيع التقارير**: في نهاية كل فترة عمل، قم بإرسال التقارير الناتجة للعملاء كإثبات على الحماية والعمليات المنفذة.

---

## 4. مثال على مسار الأوامر
```bash
# 1. إضافة شركة جديدة
python admin_cli.py add_client company_z "Z-Crypto" secret_token_999

# 2. إضافة مفتاح API للشركة
python admin_cli.py add_key company_z binance KEY SECRET

# 3. تشغيل البوت للبدء في المراقبة والحماية
python bot.py

# 4. سحب يدوي (مثال)
python admin_cli.py withdraw company_z binance BTC 0.5 [ADDRESS]

# 5. عرض سجل المعاملات
python admin_cli.py history
```
